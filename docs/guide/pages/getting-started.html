Getting started

The website runs on the data already in the repository, so you need no NASA account to try it. Rebuilding the data from NISAR is a separate step, covered in Pipeline.

What you need

ForInstall
The websiteNode.js 20.19 or later (22 LTS recommended), with npm
The pipeline and the request serverMiniconda or Anaconda, for the sartale environment in environment.yml (Python 3.12, NumPy, SciPy, h5py, rasterio, GDAL, pyproj, Pillow, requests, pytest)
Rebuilding data from NISARA free NASA Earthdata login, saved in ~/.netrc

Run the website

git clone https://github.com/saeedahmadicp/SARtale.git
cd SARtale
npm --prefix app install
npm --prefix app run dev        # opens on http://localhost:5173

The site opens on the story page. Use the header to switch to Lake Watch and How we know.

Run the tests

npm --prefix app test -- --run   # app tests, including the wording check
npm --prefix app run build       # type-check, then build into app/dist/

For the Python side, create the environment once, then run pytest from processing/:

conda env create -f environment.yml
cd processing
conda run -n sartale pytest tests -q

Both suites run offline. The Python tests use small synthetic NISAR files built in tests/gcov_fixture.py, not real downloads.

Try the "Add a lake" form

The form needs the small request server. Start it next to the dev server, in a second terminal:

cd processing
conda run -n sartale python -m sartale.run_pipeline lake-requests-serve
# listening on 127.0.0.1:8787, saving to data/lake_requests.sqlite

The dev server forwards /api to it. Without the server, the form says "Requests are not open on this copy of the site." and the rest of the site works as normal. See Lake request API.

Port already in use? If 8787 or 5173 is taken, another copy is probably running. Stop it, or pass --port to the server and -- --port 5174 to npm run dev. The dev proxy always points at 127.0.0.1:8787, so move the server only if you also change app/vite.config.ts.
