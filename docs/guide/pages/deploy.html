Deploying

The website is static files, so any static host can serve it. The request server is optional: without it, the site works and the form says requests are not open.

The website alone

npm --prefix app ci
npm --prefix app run build      # writes app/dist/

Upload the contents of app/dist/ to any static host (GitHub Pages, Netlify, an S3 bucket, nginx). The build uses relative paths, so it also works from a sub-folder such as https://example.org/sartale/. Check it locally first with npm --prefix app run preview.

With the request server

Run the server on a machine you control, behind a reverse proxy that adds HTTPS:

cd processing
conda run -n sartale python -m sartale.run_pipeline lake-requests-serve \
  --host 127.0.0.1 --port 8787 --origin https://lakes.example.org

Then either:

  • Same origin: have the proxy send /api/ on the site's own domain to 127.0.0.1:8787. Build the app as above.
  • Separate origin: serve the API on its own domain and build the app with VITE_REQUESTS_API=https://api.example.org/api npm --prefix app run build.

In both cases --origin must be the exact origin the site is served from, scheme and port included. Browser requests from any other origin are refused.

Rate limits behind a proxy. The server limits requests per client address. Behind a reverse proxy it sees the proxy's address, so all visitors share one limit of 5 requests per hour. Set a per-client limit in the proxy as well if the site is public.

Back up and review

  • The whole request state is one SQLite file (--db). Back it up with the server stopped, or with sqlite3 data/lake_requests.sqlite ".backup backup.sqlite".
  • Review requests regularly with lake-requests-list; at 200 open requests the server stops taking new ones.
  • The server is built for a demo or a small pilot. For wider use, put it behind a proxy with time limits for slow clients, and keep it off the open internet without one.

Updating the data

After running the pipeline, commit app/public/data/lakes.json and the changed pictures, then rebuild and upload the site. The app reads the data at start-up, so nothing else needs to change.
