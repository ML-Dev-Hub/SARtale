Data files

Two JSON files carry the project: lakes_in.json, the register the team edits, and lakes.json, which the pipeline writes and the app reads.

lakes_in.json

processing/lakes_in.json is a list with one object per lake:

{
  "id": "attabad",                                  // lower case, digits and _; also the picture folder name
  "name": "Attabad Lake (landslide-dammed control)",
  "lon": 74.86, "lat": 36.33,                       // decimal degrees, WGS 84
  "role": "control",                                // "watch", "story" or "control"
  "coord_source": "SARtale spike 2 Nov 2026: lake visible in NISAR passes",
  "outline": "outlines/attabad_osm.geojson",        // or null for a 1 km circle
  "downstream": null,                               // optional: what lies downstream
  "downstream_source": null
}
RoleMeaning
watchA lake SARtale screens. Requests accepted from the website get this role by default.
storyA lake that also appears in the story, such as Shisper.
controlA known, permanent lake used to check the method. It is listed last and drawn with a dashed border.

lakes.json

app/public/data/lakes.json is written by lakes-build and never edited by hand. Its top level:

KeyContents
version, built, cridFile version, build time, and the NISAR release used (P05023)
notesBuild notes shown as method limits
cloud_windowThe dates counted in the headline
constantsThe method constants from config.py, so page text matches the build
lakesOne object per lake (below)
checksSentinel-2 comparison rows from lake_checks.json. A row with only lake and note means no comparison was possible; the app shows it as a note.

Each lake carries its register fields plus:

KeyContents
statusstatus, track, latest_date, looks, change_km2, noise_km2 and a plain reason
seriesEvery pass: date, track, area_km2, observable_share, and excluded (null, or the reason it was left out)
excludedThe passes left out, as {"pass", "reason"}
imagesPaths, relative to data/, of latest_hh and water
boundsThe window's [west, south, east, north] in degrees
area_label, outline_source, limits, directions, cloud_window_looksWhat the area measures, the outline's source, lake-specific limits, the viewing directions seen (A, D) and looks in the cloud window

A sample pass from series:

{ "date": "2026-06-18", "track": "055A", "area_km2": 2.665, "observable_share": 0.675, "excluded": null }

Pictures

For each lake, lakes-build writes two lossless WebP files to app/public/data/lakes/<id>/: latest_hh.webp, a grey HH picture of the latest valid pass, and water.webp, a transparent layer with water in blue and shadow-prone ground hatched. Both cover the 6 km window on the UTM grid, north up.
