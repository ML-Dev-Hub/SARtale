Lake request API

A small HTTP server that takes "Add a lake" requests, saves them in SQLite and counts NISAR passes over each point from NASA's CMR catalogue. It never downloads NISAR data. It uses the Python standard library only.

Start the server#

cd processing
conda run -n sartale python -m sartale.run_pipeline lake-requests-serve
OptionDefaultUse
--host127.0.0.1Address to listen on. Use 0.0.0.0 only behind a proxy you control
--port8787Port
--dbdata/lake_requests.sqliteThe database file; data/ is git-ignored
--originhttp://localhost:5173The one site origin allowed to read replies and to send requests

Routes#

GET /api/health#

200  { "ok": true, "open": 2 }

open is the number of requests not yet accepted or rejected.

GET /api/lake-requests#

Every open request, newest first. The source a visitor typed, the requester's address and any raw error are never returned.

200  { "requests": [
  { "id": 4, "name": "Moraine lake above Gulmit", "lat": 36.2, "lon": 73.9,
    "state": "searched", "passes": 14, "tracks": ["055A", "156A"],
    "first": "2026-06-18", "last": "2026-10-23", "reason": null,
    "created": "2026-11-05T09:12:00Z" }
] }

POST /api/lake-requests#

Puts a lake forward. Send JSON with Content-Type: application/json:

POST /api/lake-requests
Content-Type: application/json

{ "name": "Moraine lake above Gulmit", "lat": 36.2, "lon": 73.9,
  "source": "Glacial lake inventory 2023, lake 412" }

On success the reply is 201 with the new request, in state queued. The catalogue search then runs in the background; poll GET /api/lake-requests to see it become searched or search_failed.

Request states#

StateMeaning
queuedSaved; the catalogue search is running
searchedThe search finished: passes, tracks, first and last are filled
search_failedThe catalogue did not answer, or answered oddly. reason says which in one short line; the raw error is kept privately for the team
acceptedThe team added the lake to lakes_in.json
rejectedThe team turned it down, with a reason

A search that finishes after the team has accepted or rejected a request does not change it.

Rules and errors#

Every error is JSON, { "error": "…" }, with a message you can show to the visitor.

StatusWhen
400Not a JSON object; lat or lon not a number; the point outside 34.4–37.6 °N, 70.8–76.6 °E; name not 2–80 characters; source not 3–200 characters; control or invisible formatting characters in the text
403A browser sent the request from a site other than --origin
404, 405Unknown path, or the wrong method
409Within 1 km of a watched lake or an open or accepted request. The message names that lake
411, 413No Content-Length, or a body over 4 KB
415The body was not sent as application/json
429More than 5 requests from one address in an hour
503200 requests are already open

The server also closes connections that stay silent for 10 seconds and serves at most 64 connections at once.

Review requests#

Only the team can accept or reject, from the command line in processing/. The HTTP API has no route that changes a request.

conda run -n sartale python -m sartale.run_pipeline lake-requests-list
conda run -n sartale python -m sartale.run_pipeline lake-requests-accept 4
conda run -n sartale python -m sartale.run_pipeline lake-requests-reject 5 --reason "No public source for the coordinate"

lake-requests-list prints each open request with its source and any raw error. lake-requests-accept appends one entry to lakes_in.json with role watch (change it with --role) and a coord_source of "Requested <date>: <source>". Running it twice does not add a duplicate. Then run the pipeline (Pipeline) to give the lake its status.

Check the source first. Accept a lake only when its coordinate has a source someone can check: an inventory, a paper, a field survey or a dated map.
